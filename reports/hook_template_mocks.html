Hook templates in Avatar Shots — picker, slots, and the edit warning

Three renderings of the same feature, escalating in surface count. Every background is a live capture of app.heygen.com/avatar/avatar-shots taken today; every overlay is built from Prism dark tokens; every template card is one of the 37 real treatments that were re-rendered on a different identity and ArcFace-scored, with its real score on it.

The decision this deck encodes: nothing is hard-locked. Every ingredient is editable, and the warning carries the consequence plus the evidence — so an edit is a choice, not a mistake. That also means a template-owned edit invalidates the example output the user picked, which is why stale is a first-class state here.

VARIANT 0

Enhance prompt resolves to a proven treatment

default-on · no new UI

The user types a rough hook. Enhance prompt — which already exists and is already on — silently matches it to the nearest mined treatment, drops in the locked scene prose, and substitutes their own subject values from Brand Kit. No picker, no new page, no new toggle. The only new pixel is one tooltip explaining what it matched.

new route

VARIANT 2 · SLOT FILL

Two zones, five ingredients, nothing locked

editable with a warning

The split is by who owns it, not by field type. Two rows are the user's and are empty by design; four came with the template and are pre-filled. Every row has the same Edit affordance — the difference is that editing a template row states its consequence first. Framing carries the identity warning because framing is what decides whether the output still looks like the customer.
